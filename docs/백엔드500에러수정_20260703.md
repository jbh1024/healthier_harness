# 백엔드 요청 파싱 오류 500 → 400 수정

- 작업일: 2026-07-03
- 배경: FE 개선 작업 중 발견한 후속 과제 — 필수 필드 누락 바디(예: 초대코드 생성 빈 바디 `{}`) 요청 시 500(COMMON_002) 반환

## 지시 내용

- 필수 필드 누락/형식 오류 요청이 500이 아닌 400으로 응답하도록 수정

## 원인

- Kotlin non-null 파라미터 DTO에 필드 누락 바디가 들어오면 Jackson `MismatchedInputException` 발생
- `GlobalExceptionHandler`에 해당 예외(Spring이 `HttpMessageNotReadableException`으로 래핑) 핸들러가 없어 최종 `Exception` 핸들러가 500 처리

## 구현 내용

`common/exception/GlobalExceptionHandler.kt`에 핸들러 2개 추가:

1. **`HttpMessageNotReadableException`** → 400 + `COMMON_001`
   - cause가 `MismatchedInputException`이면 누락 필드 경로를 추출해 `"role: 필수 값이 누락되었거나 형식이 올바르지 않습니다"` 형태로 응답
   - 깨진 JSON 등 필드 특정 불가 시 `"요청 본문이 올바르지 않습니다"`
2. **`MethodArgumentTypeMismatchException`** → 400 + `COMMON_001`
   - 경로 변수/쿼리 파라미터 타입 오류 (예: `GET /academies/abc`)

## 검증 결과

- `GlobalExceptionHandlerTest` 통합 테스트 3건 신규 작성(@SpringBootTest + MockMvc), 전체 테스트 통과
- 라이브 확인: 초대코드 빈 바디 400 + 필드명 메시지, 로그인 빈 바디 400, `/academies/abc` 400

## 의사결정

- 에러 코드는 기존 `COMMON_001`(잘못된 입력) 재사용 — 신규 코드 불필요
- 필드명 노출은 안전(스키마는 Swagger로 이미 공개)하며 클라이언트 디버깅에 유용
