# Backend ktlint/detekt 플러그인 설정

- 작업일: 2026-07-04
- 배경: rule 문서(`static_analyze.md`)에 안내된 `ktlintCheck`/`detekt` 태스크가 Gradle 플러그인 미설정으로 존재하지 않던 문제

## 지시 내용

- ktlint/detekt Gradle 플러그인 설정 추가

## 구현 내용

`backend/build.gradle.kts`:
- `org.jlleitschuh.gradle.ktlint` 12.2.0 + ktlint 엔진 `1.5.0` 명시
- `io.gitlab.arturbosch.detekt` 1.23.8 + detekt 컨피규레이션의 Kotlin `2.0.21` 고정
- `config/detekt/detekt.yml` 신규 작성 (`buildUponDefaultConfig = true`)

## 의사결정

| 결정 | 근거 |
|------|------|
| ktlint 엔진 1.5.0 고정 | 플러그인 기본 엔진이 프로젝트 Kotlin 2.1.10 클래스패스와 충돌 (`KtTokens.HEADER_KEYWORD` 오류) |
| detekt용 Kotlin 2.0.21 고정 | detekt 1.23.x는 Kotlin 2.0.21 컴파일 — 2.1.10이 주입되면 실행 거부. detekt 공식 가이드 방식 |
| `MagicNumber`/`ForbiddenComment` 비활성 | HTTP 상태·토큰 만료 등 도메인 수치와 미구현 기능 TODO 마커는 노이즈 대비 실익 낮음 |
| `UnusedParameter`에 `ignoreAnnotated: [PathVariable]` | 컨트롤러 경로 변수는 라우팅 매핑상 시그니처 제거 불가 |
| `ThrowsCount: 6`, `LongParameterList` 완화 | 가드절 검증(자격/권한/정원)과 JPA 엔티티·생성자 주입 패턴 수용 |

## 지적 사항 코드 수정 (규칙 완화 대신 수정이 적절했던 건)

- ktlintFormat 일괄 포맷팅 적용 (139개 파일)
- Board 도메인 와일드카드 import 2건 → 명시 import
- `DashboardService` 미사용 `academyMemberRepository` 주입 제거 (데드코드)
- `JwtTokenProvider` 의도적 예외 무시 catch 변수명 `ignored`로 변경
- 컨텍스트 로드 테스트 빈 블록에 목적 주석 추가

## 검증 결과

- `./gradlew ktlintCheck detekt compileKotlin test` 전체 통과

## CI 연동 (2026-07-04 추가)

- `.github/workflows/ci.yml` 신규 작성 (기존 워크플로우 부재 — README의 GitHub Actions 안내와 달리 미생성 상태였음)
- **backend** 잡: JDK 21(temurin) + Gradle 캐시 → `ktlintCheck detekt` → `build`(test 포함), 실패 시 테스트 리포트 아티팩트 업로드
- **frontend** 잡: Flutter stable + pub 캐시 → `dart analyze --fatal-infos` → `flutter test`
- 트리거: main/develop 브랜치 push 및 PR
- rule 문서(`static_analyze.md`)의 "CI 미강제" 원칙을 "CI 강제"로 갱신 (사용자 지시)
- 검증: CI와 동일 명령을 로컬에서 실행해 전체 통과 확인
